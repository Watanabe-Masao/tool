## 計算機能

### 計算モード

#### 1. 定額売価→計量加工
**用途**: 箱単位で仕入れ、100g単位で販売する場合

**計算フロー**:
1. 1個あたりの原価・売価・重量を入力
2. 加工前の100gあたり原価・売価・値入率を計算
3. 加工後重量から歩留まり率を計算
4. 加工後の100gあたり原価・売価・値入率を計算

**表示項目**:
- 加工前100g単価、売価、値入率
- 歩留まり率
- 加工後100g原価、売価、値入率
- 仕上がり売価と差額

#### 2. 計量売価→計量加工
**用途**: 100g単位で仕入れ、100g単位で販売する場合

**計算フロー**:
1. 1箱あたりの原価・売価・重量を入力
2. 加工前の100gあたり原価・売価・値入率を計算
3. サンプル重量から歩留まり率を計算
4. 加工後の100gあたり原価・売価・値入率を計算

### 歩留まり率の計算方法

#### 重量から計算
- 加工前重量と加工後重量を入力
- 歩留まり率 = (加工後重量 / 加工前重量) × 100

#### 歩留まり率直接入力
- 既知の歩留まり率を直接入力
- 経験値やデータベースから参照する場合に使用

### シミュレーション機能

#### 商品化シミュレーション
**目的**: パック化後の実売価格を計算

**入力項目**:
- 1パックに入れる予定重量（g）
- 消耗品費（円）

**出力項目**:
- パック原価
- パック売価
- パック値入率

**計算式**:
```
パック原価 = 加工後100g原価 × (重量 / 100) + 消耗品費
パック売価 = 加工後100g売価 × (重量 / 100)
パック値入率 = ((パック売価 - パック原価) / パック売価) × 100
```

#### 値引きシミュレーション
**目的**: 値引後の粗利率を確認

**入力項目**:
- 値引率（%）：スライダーで0〜50%まで調整可能

**出力項目**:
- 値引後最終粗利率

**計算式**:
```
値引後粗利率 = 値入率 / (1 - 値引率/100)
```

#### 逆算シミュレーション
**目的**: 目標値入率から必要な値を逆算

**操作方法**:
1. 「値引後最終粗利率」カードをクリック/タップ
2. 逆算したい項目を選択
3. 目標値入率を入力

**逆算可能な項目**:

1. **重量（g）**
   - 目標値入率を達成するための必要重量

2. **100gあたり売価（円）**
   - 目標値入率を達成するための必要売価

3. **原価（円）**
   - 定額モード: 1個あたりの原価
   - 計量モード: 1箱あたりの原価

4. **歩留まり率（%）/ 加工後重量（g）**
   - 入力方法に応じて自動切替
   - 重量から計算: 加工後重量
   - 直接入力: 歩留まり率

5. **値引率（%）**
   - 目標粗利率を達成するための必要値引率

**エラーハンドリング**:
- 計算不可能な場合、具体的なエラーメッセージを表示
- 有効範囲を提示（例: 「目標値入率は25.00%以下で設定してください」）

## 歩留まり統計機能

### 概要
**目的**: 複数サンプルの加工前後の重量データから歩留まり率を統計的に分析し、信頼性の高い代表値を導出する。

**用途**:
- 新商品の歩留まり率を決定する際の根拠データ収集
- 既存商品の歩留まり率の見直し
- サンプル数が十分かどうかの判断
- データのばらつきや外れ値の確認

### データ入力

#### Excel風テーブル
**機能**:
- スプレッドシート風のUI
- 加工前重量（g）と加工後重量（g）を入力
- 歩留まり率を自動計算して表示

**操作**:
- セルをクリックして数値を入力
- Enterキーで次の行に移動
- 最終行に入力すると自動的に新しい行が追加

**データ要件**:
- 最低2件以上のデータが必要
- 加工前重量と加工後重量の両方が入力されたデータのみ統計分析に使用

**計算式**:
```
歩留まり率 = (加工後重量 / 加工前重量) × 100
```

### 基本統計量

#### データ数
- 有効なデータの件数
- 両方の重量が入力されたデータのみカウント

#### 最大値・最小値・範囲
- **最大値**: データセット内の最大値
- **最小値**: データセット内の最小値
- **範囲（レンジ）**: 最大値 - 最小値
- データのばらつきの広さを示す

#### 平均値（算術平均）
**計算式**:
```
x̄ = (x₁ + x₂ + ... + xₙ) / n
```
- 全データの合計をデータ数で割った値
- データの中心的な傾向を表す

#### 中央値（メディアン）
**計算方法**:
- データを昇順に並べる
- nが奇数: 中央の値
- nが偶数: 中央2つの値の平均

**特徴**:
- 外れ値の影響を受けにくい
- 歪んだ分布に適している

#### 標準偏差（σ）
**計算式**:
```
σ = √(Σ(xᵢ - x̄)² / n)
```
- データのばらつき（散らばり具合）を示す
- 値が大きいほどデータが平均値から離れている

#### 変動係数（CV）
**計算式**:
```
CV = (σ / x̄) × 100 (%)
```
- 標準偏差を平均値で割った値
- 異なる単位や規模のデータのばらつきを比較できる
- 10%以下: ばらつきが小さい
- 10-20%: 中程度のばらつき
- 20%以上: ばらつきが大きい

### 四分位数と分布

#### 第1四分位数（Q1）
- データを昇順に並べたとき、25%の位置にある値
- 下位25%のデータの境界

#### 第3四分位数（Q3）
- データを昇順に並べたとき、75%の位置にある値
- 上位25%のデータの境界

#### 四分位範囲（IQR）
**計算式**:
```
IQR = Q3 - Q1
```
- 中央50%のデータの広がりを示す
- 外れ値の影響を受けにくい指標

#### 歪度（Skewness）
**計算式**:
```
Skewness = Σ((xᵢ - x̄) / σ)³ / n
```
- 分布の左右対称性を示す
- 0に近い: 左右対称（正規分布に近い）
- 正の値: 右に裾が長い（高い値の外れ値がある）
- 負の値: 左に裾が長い（低い値の外れ値がある）

#### 尖度（Kurtosis）
**計算式**:
```
Kurtosis = Σ((xᵢ - x̄) / σ)⁴ / n - 3
```
- 分布の尖り具合を示す
- 0: 正規分布と同じ尖り具合
- 正の値: 正規分布より尖っている（外れ値が多い）
- 負の値: なだらか（データが均一）

### 信頼区間分析

#### 正規分布におけるσ範囲
データが正規分布に従うと仮定した場合の信頼区間。

**σ1範囲（68.3%）**:
```
[x̄ - σ, x̄ + σ]
```
- 約68.3%のデータがこの範囲に含まれる

**σ2範囲（95.4%）**:
```
[x̄ - 2σ, x̄ + 2σ]
```
- 約95.4%のデータがこの範囲に含まれる

**σ3範囲（99.7%）**:
```
[x̄ - 3σ, x̄ + 3σ]
```
- 約99.7%のデータがこの範囲に含まれる
- この範囲外はほぼ外れ値と見なせる

### サンプルサイズの妥当性判断

#### 必要サンプルサイズの計算
**目的**: 統計的に十分なサンプル数を確保できているかを判定

**計算式**:
```
n = (Z × σ / E)²
```
- Z: 信頼水準に対応するZ値
- σ: 標準偏差
- E: 許容誤差

**信頼水準とZ値の対応**:
- 90%: Z = 1.645
- 95%: Z = 1.960（最も一般的）
- 99%: Z = 2.576

**許容誤差（E）**:
- 推定値と真の値の間で許容できる誤差の大きさ
- 小さいほど精度が高くなるが、より多くのサンプルが必要
- 例: 2.0%なら真の値±2.0%の範囲で推定したい

**判定基準**:
- 実際のサンプル数 ≥ 必要サンプル数: 妥当
- 実際のサンプル数 < 必要サンプル数: 不足

**表示内容**:
- 実際のサンプル数
- 必要サンプル数（小数点以下切り上げ）
- 判定結果（妥当/不足）
- 具体的な説明とアクション

### 外れ値検出（IQR法）

#### IQR法による外れ値検出
**計算式**:
```
外れ値 = データ < Q1 - 1.5×IQR または データ > Q3 + 1.5×IQR
```

**検出範囲**:
```
正常範囲 = [Q1 - 1.5×IQR, Q3 + 1.5×IQR]
```

**表示**:
- 外れ値の件数
- 正常範囲の値
- 外れ値のリスト（行番号と値）

**操作**:
- 外れ値をチェックボックスで選択
- 「すべて選択」「すべて解除」ボタン
- 「外れ値を含む行をテーブルから削除」ボタン
- 削除後は統計が自動再計算される

**視覚化**:
- テーブル上で外れ値を含む行をハイライト表示
- 背景色を赤系に変更
- 行番号を強調表示

### 推奨代表値

#### 自動判定ロジック
**基準**: 歪度の絶対値

**判定ルール**:
```
|歪度| ≤ 0.5 → 平均値を推奨
|歪度| > 0.5 → 中央値を推奨
```

**理由**:
- **平均値**: 分布が対称的な場合に適している
- **中央値**: 分布が歪んでいる場合や外れ値がある場合に適している

**表示内容**:
- 推奨される代表値（平均値 or 中央値）
- 判定理由の説明
- 実際の値

### グラフ表示（ECharts）

#### 対応グラフ種類

**1. 箱ひげ図（Box Plot）**
- データの分布を5つの数値で要約
- 最小値、Q1、中央値、Q3、最大値
- 外れ値を点で表示

**2. ヒストグラム（Histogram）**
- データの度数分布を棒グラフで表示
- ビンの数は自動計算（Sturgesの公式）
- データの偏りを視覚的に確認

**3. 散布図（Scatter Plot）**
- 各データ点をプロット
- データの傾向やパターンを把握
- 加工前重量と歩留まり率の関係を表示

**4. 正規分布曲線（Normal Distribution）**
- 理論的な正規分布曲線をヒストグラムに重ねて表示
- 実際のデータが正規分布に従うかを確認

**5. Q-Qプロット（Q-Q Plot）**
- 実際のデータと理論的な正規分布を比較
- データが正規分布に従う場合、点は直線上に並ぶ
- 正規性の検定に使用

#### 分析対象の切り替え
- **歩留まり率**: 最も一般的な分析対象
- **加工前重量**: サンプルの元の重量の分布を確認
- **加工後重量**: 加工後の重量の分布を確認

**使い方**:
1. 「表示する統計」ドロップダウンで対象を選択
2. 「グラフ種類」ドロップダウンでグラフタイプを選択
3. グラフが自動的に更新される

## セッション管理機能

### セッション自動保存

**概要**: ページリロード後も入力値を自動的に保持する機能

**動作仕様**:
- **保存タイミング**: 入力値が変更されるたびに自動保存
- **保存先**: localStorage（`yieldCalculatorSession`キー）
- **有効期限**: 24時間（期限切れデータは自動削除）
- **保存内容**:
  - 選択中のモード（定額/計量/歩留まり統計）
  - 歩留まり率の入力方法（重量から計算/直接入力）
  - すべての入力フィールドの値
  - 商品化シミュレーションの値
  - 歩留まり統計のテーブルデータ

**実装関数**:
- `saveSessionState(mode)`: 現在の状態をlocalStorageに保存
- `restoreSessionState()`: localStorageからセッションデータを復元（有効期限チェック付き）
- `clearSessionState()`: セッションデータをクリア
- `applySessionState(sessionData)`: セッションデータから入力フィールドを復元

**セッションデータ構造**:
```javascript
{
  mode: "fixed" | "weight" | "yieldStats",
  yieldMethod: "calculate" | "direct",
  timestamp: 1706400000000,  // 保存日時
  inputs: {
    // モード別の入力値
  },
  simulation: {
    expWeight: "100",
    consumable: "10"
  },
  tableData: [
    // 歩留まり統計のテーブルデータ（yieldStatsモードのみ）
  ]
}
```

**使用例**:
1. ユーザーが入力を開始
2. 入力値が自動的にlocalStorageに保存される
3. ブラウザを閉じる/ページをリロードする
4. アプリ起動時に自動的に入力値が復元される
5. 24時間経過後は自動的にクリアされる

## データ管理機能

### 保存機能

#### カテゴリー優先の保存フロー
**手順**:
1. 計算完了後、「💾 この計算を保存」をクリック
2. **カテゴリーを選択**（野菜/果実）
3. **商品名を入力**
   - カテゴリーに応じた商品名候補が表示される
   - 既存の商品名から選択または新規入力
4. 保存ボタンをクリック

**カテゴリー別フィルタリング**:
- カテゴリーを選択すると、そのカテゴリーに属する商品名のみが表示
- 例: 「野菜」を選択 → データベース内の野菜カテゴリーの商品名のみ表示

**保存されるデータ**:
- 商品名

- 歩留まり率

**その他の情報**:

- **全ステップの結果を即座に表示**（v3.2で改善）
  - 加工前の原価・売価・値入率
  - 歩留まり率
  - 加工後の原価・売価・値入率

  - 履歴読み込み直後は保存ボタンを無効化
  - 入力値を変更すると保存ボタンが有効化される

**編集** ✏️:

## PWA機能

### オフライン対応

#### Service Worker
**キャッシュ戦略**: Network First with Cache Fallback

**動作**:
1. まずネットワークから最新版を取得
2. ネットワークが利用できない場合、キャッシュから提供
3. 取得した最新版をキャッシュに保存

**キャッシュ対象**:
- HTML、CSS、JavaScript
- アプリアイコン
- manifest.json

**バージョン管理**:
```javascript
CACHE_VERSION = 3
CACHE_BUILD = 'YYYYMMDD-XXX'
CACHE_NAME = 'yield-calculator-v3-20250125-002'
```

#### 自動更新通知
**仕組み**:
1. 1時間ごとに新バージョンをチェック
2. 新バージョンが検出されたら通知を表示
3. ユーザーが「更新」ボタンをクリック
4. 新バージョンを即座に適用

**通知UI**:
```
🔄 新しいバージョンが利用可能です [更新] [✕]
```

### ホーム画面に追加

#### manifest.json
**設定内容**:
- アプリ名: 「歩留まり計算ツール」
- 短縮名: 「歩留まり計算」
- 表示モード: standalone（フルスクリーン）
- 向き: portrait-primary（縦向き）
- テーマカラー: #5c6bc0
- アイコン: 72px〜512px（8サイズ）

#### インストール体験
**Android（Chrome）**:
1. 「ホーム画面に追加」プロンプトが自動表示
2. または メニュー → 「ホーム画面に追加」

**iOS（Safari）**:
1. 共有ボタン → 「ホーム画面に追加」

**PC（Chrome/Edge）**:
1. アドレスバーのインストールアイコンをクリック

### キャッシュ最適化

**メタタグ**:
```html
<meta http-equiv="Cache-Control" content="no-cache, no-store, must-revalidate" />
<meta http-equiv="Pragma" content="no-cache" />
<meta http-equiv="Expires" content="0" />
```

- **クリック**: ?マークをクリックすると詳細な計算式がモーダルで表示

**スマートフォンでの動作**:
- **タップ**: ?マークをタップすると詳細な計算式がモーダルで表示（ツールチップなし）

**モーダル表示内容**:
- 計算式名
- 数式表記
- 詳細な説明
- 計算例

**対応項目** (v3.4):
- 基本統計量: 最大値、最小値、範囲、平均値、中央値、標準偏差、変動係数（CV）
- 四分位数: Q1、Q3、IQR
- 分布の形状: 歪度、尖度
- 正規分布の信頼区間: σ1範囲、σ2範囲、σ3範囲
- サンプルサイズ妥当性: 必要サンプルサイズ
- 外れ値検出: IQR法
- 推奨代表値: 平均値 vs 中央値
- **許容誤差（E）**: 推定値と真の値の間で許容できる誤差
- **信頼水準**: 推定値が正しい範囲に含まれる確率

**技術実装**:
- ツールチップ: ブラウザネイティブの`title`属性を使用
- モーダル: カスタムモーダルコンポーネント
- データ属性: `data-formula-name`, `data-formula`, `data-formula-desc`, `data-formula-example`

## データ構造

### IndexedDB スキーマ

**データベース名**: YieldCalculatorDB
**ストア名**: calculations
**キー**: 自動インクリメント ID

**インデックス**:
- timestamp: 保存日時
- name: 商品名
- mode: 計算モード
- category: カテゴリー

**データ構造**:
```javascript
{
  id: number,                 // 自動インクリメント
  name: string,               // 商品名
  category: string,           // カテゴリー（vegetable/fruit）
  mode: string,               // 計算モード（fixed/weight）
  input: {                    // 入力値
    mode: string,
    yieldMethod: string,      // 歩留まり計算方法
    unitCost: number,         // 1個あたり原価（定額モード）
    unitPrice: number,        // 1個あたり売価（定額モード）
    boxCost: number,          // 1箱あたり原価（計量モード）
    boxPrice: number,         // 1箱あたり売価（計量モード）
    beforeWeight: number,     // 加工前重量
    afterWeight: number,      // 加工後重量
    yieldRate: number,        // 歩留まり率
    afterPrice100: number,    // 加工後100g売価
    expWeight: number,        // パック重量
    consumable: number        // 消耗品費
  },
  result: {                   // 計算結果
    yr: number,               // 歩留まり率
    bc: number,               // 加工前100g原価
    bp: number,               // 加工前100g売価
    ac: number,               // 加工後100g原価
    ap: number,               // 加工後100g売価
    bm: number,               // 加工前値入率
    am: number,               // 加工後値入率
    yieldRate: number,        // 歩留まり率（スナップショット）
    afterMarkup: number,      // 加工後値入率（別名）
    discountGross: number     // 値引後最終粗利率
  },
  product: {                  // 商品化データ
    price: number,            // パック売価
    markup: number,           // パック値入率
    cost: number              // パック原価
  },
  timestamp: number,          // 保存日時（ミリ秒）
  createdAt: string,          // 作成日時（ISO文字列）
  updatedAt: string           // 更新日時（ISO文字列）
}
```

## v3.5 更新内容 (2025-01-28)

### セッション管理機能の追加
- **自動保存**: ページリロード後も入力値を保持
  - 24時間の有効期限付き自動保存
  - すべての入力フィールド、選択中のモード、計算方法を保持
  - 歩留まり統計のテーブルデータも保存対象

### 保存ボタンの状態管理改善
- **履歴読み込み後の制御**:
  - 履歴から読み込んだ計算は、変更がない場合は保存ボタンを無効化
  - 入力値を変更すると保存ボタンが有効化される
- **フラグベースの状態管理**:
  - `isFromHistory`: 履歴から読み込まれた計算かどうか
  - `hasUnsavedChanges`: 未保存の変更があるかどうか
- **重複保存の防止**: 同じ計算を複数回保存することを防ぐ

### AppState状態管理の拡張
- `markAsFromHistory()`: 履歴から読み込んだことをマーク
- `markAsNewCalculation()`: 新規計算としてマーク
- `markAsChanged()`: 変更があったことをマーク
- `markAsSaved()`: 保存済みとしてマーク
- `isFromHistoryRecord()`: 履歴からの読み込みかどうかを判定
- `hasChanges()`: 未保存の変更があるかどうかを判定

### フィルタリング機能の改善
- 歩留まり統計モードのフィルタリング問題を修正
- `yieldMethod` が未保存の古いデータでもフィルタが正常に動作
