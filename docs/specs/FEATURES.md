## 計算機能

### 計算モード

#### 1. 定額売価→計量加工
**用途**: 箱単位で仕入れ、100g単位で販売する場合

**計算フロー**:
1. 1個あたりの原価・売価・重量を入力
2. 加工前の100gあたり原価・売価・値入率を計算
3. 加工後重量から歩留まり率を計算
4. 加工後の100gあたり原価・売価・値入率を計算

**表示項目**:
- 加工前100g単価、売価、値入率
- 歩留まり率
- 加工後100g原価、売価、値入率
- 仕上がり売価と差額

#### 2. 計量売価→計量加工
**用途**: 100g単位で仕入れ、100g単位で販売する場合

**計算フロー**:
1. 1箱あたりの原価・売価・重量を入力
2. 加工前の100gあたり原価・売価・値入率を計算
3. サンプル重量から歩留まり率を計算
4. 加工後の100gあたり原価・売価・値入率を計算

#### 3. 歩留まり統計
**用途**: 複数サンプルの統計分析

詳細は[歩留まり統計機能](#歩留まり統計機能)を参照

#### 4. 複数パターン分析 🆕
**用途**: 異なる原価・売価シナリオの一括比較

詳細は[複数パターン分析機能](#複数パターン分析機能)を参照

### 歩留まり率の計算方法

#### 重量から計算
- 加工前重量と加工後重量を入力
- 歩留まり率 = (加工後重量 / 加工前重量) × 100

#### 歩留まり率直接入力
- 既知の歩留まり率を直接入力
- 経験値やデータベースから参照する場合に使用

### シミュレーション機能

#### 商品化シミュレーション
**目的**: パック化後の実売価格を計算

**入力項目**:
- 1パックに入れる予定重量（g）
- 消耗品費（円）

**出力項目**:
- パック原価
- パック売価
- パック値入率

**計算式**:
```
パック原価 = 加工後100g原価 × (重量 / 100) + 消耗品費
パック売価 = 加工後100g売価 × (重量 / 100)
パック値入率 = ((パック売価 - パック原価) / パック売価) × 100
```

#### 値引きシミュレーション
**目的**: 値引後の粗利率を確認

**入力項目**:
- 値引率（%）：スライダーで0〜50%まで調整可能

**出力項目**:
- 値引後最終粗利率

**計算式**:
```
値引後粗利率 = 値入率 / (1 - 値引率/100)
```

#### 逆算シミュレーション
**目的**: 目標値入率から必要な値を逆算

**操作方法**:
1. 「値引後最終粗利率」カードをクリック/タップ
2. 逆算したい項目を選択
3. 目標値入率を入力

**逆算可能な項目**:

1. **重量（g）**
   - 目標値入率を達成するための必要重量

2. **100gあたり売価（円）**
   - 目標値入率を達成するための必要売価

3. **原価（円）**
   - 定額モード: 1個あたりの原価
   - 計量モード: 1箱あたりの原価

4. **歩留まり率（%）/ 加工後重量（g）**
   - 入力方法に応じて自動切替
   - 重量から計算: 加工後重量
   - 直接入力: 歩留まり率

5. **値引率（%）**
   - 目標粗利率を達成するための必要値引率

**エラーハンドリング**:
- 計算不可能な場合、具体的なエラーメッセージを表示
- 有効範囲を提示（例: 「目標値入率は25.00%以下で設定してください」）

## 複数パターン分析機能 🆕

### 概要
異なる原価・売価の複数シナリオを一括で比較分析する機能です。時期や仕入先による価格変動の影響を可視化し、最適な販売戦略を立てるために使用します。

### 主要機能

#### 1. パターン入力テーブル
**機能**:
- 複数の原価・売価パターンを一覧表示
- 各パターンの1個原価、1個売価、加工後設定売価を入力
- パターンの追加・削除が可能

**入力項目**:
- 1個原価（円）
- 1個売価（円）
- 加工後設定売価（100g/円）

#### 2. プリセット管理 🆕
**目的**: よく使う原価・売価の組み合わせを保存・再利用

**機能**:
- **プリセット保存**: パターン名、カテゴリー、メモを設定して保存
- **プリセット選択**: 保存済みプリセットから複数選択して一括入力
- **プリセット編集**: 既存プリセットの内容を更新
- **プリセット削除**: 不要なプリセットを削除
- **エクスポート/インポート**: JSON形式でプリセットをバックアップ・復元

**実装モジュール**:
- `scripts/multi-pattern-presets.js` (463行): プリセット管理ロジック
- IndexedDBの `multiPatternPresets` ストアに保存

#### 3. 統計値の自動読み込み 🆕
**機能**:
- 歩留まり統計モードで計算した統計値（平均値・中央値）を自動入力
- 分析対象（歩留まり率、加工前重量、加工後重量）を選択可能
- 読み込みタイプ（平均値・中央値）を選択可能

**ワークフロー**:
1. 歩留まり統計モードでデータを分析
2. 複数パターン分析モードに切り替え
3. 「統計から読み込み」ボタンをクリック
4. 分析対象と読み込みタイプを選択
5. 統計値が各パターンの入力フィールドに自動入力

**実装モジュール**:
- `scripts/multi-pattern-stats-loader.js` (210行): 統計値読み込みロジック

#### 4. 比較分析表示
**出力項目**:
- 各パターンの加工後100g原価
- 各パターンの値入率
- 各パターンの粗利額（100gあたり）
- 最高値入率のパターンをハイライト表示

**視覚化**:
- カラーコーディング（緑: 良好、黄: 警告）
- 最適パターンの強調表示

### ユースケース

#### ケース1: 季節による仕入価格変動
**状況**: トマトの仕入価格が季節で変動
- 夏季: 1個150円
- 冬季: 1個300円

**分析方法**:
1. 各季節のパターンを入力
2. 売価を統一して比較
3. 各季節の粗利率を確認
4. 販売戦略を決定

#### ケース2: 複数仕入先の比較
**状況**: 3つの仕入先から異なる価格で仕入可能

**分析方法**:
1. 各仕入先のパターンをプリセットとして保存
2. プリセットから一括読み込み
3. 値入率と粗利額を比較
4. 最適な仕入先を選定

## 歩留まり統計機能

### 概要
**目的**: 複数サンプルの加工前後の重量データから歩留まり率を統計的に分析し、信頼性の高い代表値を導出する。

**用途**:
- 新商品の歩留まり率を決定する際の根拠データ収集
- 既存商品の歩留まり率の見直し
- サンプル数が十分かどうかの判断
- データのばらつきや外れ値の確認

### データ入力

#### Excel風テーブル
**機能**:
- スプレッドシート風のUI
- 加工前重量（g）と加工後重量（g）を入力
- 歩留まり率を自動計算して表示

**操作**:
- セルをクリックして数値を入力
- Enterキーで次の行に移動
- 最終行に入力すると自動的に新しい行が追加

**データ要件**:
- 最低2件以上のデータが必要
- 加工前重量と加工後重量の両方が入力されたデータのみ統計分析に使用

**計算式**:
```
歩留まり率 = (加工後重量 / 加工前重量) × 100
```

### 基本統計量

#### データ数
- 有効なデータの件数
- 両方の重量が入力されたデータのみカウント

#### 最大値・最小値・範囲
- **最大値**: データセット内の最大値
- **最小値**: データセット内の最小値
- **範囲（レンジ）**: 最大値 - 最小値
- データのばらつきの広さを示す

#### 平均値（算術平均）
**計算式**:
```
x̄ = (x₁ + x₂ + ... + xₙ) / n
```
- 全データの合計をデータ数で割った値
- データの中心的な傾向を表す

#### 中央値（メディアン）
**計算方法**:
- データを昇順に並べる
- nが奇数: 中央の値
- nが偶数: 中央2つの値の平均

**特徴**:
- 外れ値の影響を受けにくい
- 歪んだ分布に適している

#### 標準偏差（σ）
**計算式**:
```
σ = √(Σ(xᵢ - x̄)² / n)
```
- データのばらつき（散らばり具合）を示す
- 値が大きいほどデータが平均値から離れている

#### 変動係数（CV）
**計算式**:
```
CV = (σ / x̄) × 100 (%)
```
- 標準偏差を平均値で割った値
- 異なる単位や規模のデータのばらつきを比較できる
- 10%以下: ばらつきが小さい
- 10-20%: 中程度のばらつき
- 20%以上: ばらつきが大きい

### 四分位数と分布

#### 第1四分位数（Q1）
- データを昇順に並べたとき、25%の位置にある値
- 下位25%のデータの境界

#### 第3四分位数（Q3）
- データを昇順に並べたとき、75%の位置にある値
- 上位25%のデータの境界

#### 四分位範囲（IQR）
**計算式**:
```
IQR = Q3 - Q1
```
- 中央50%のデータの広がりを示す
- 外れ値の影響を受けにくい指標

#### 歪度（Skewness）
**計算式**:
```
Skewness = Σ((xᵢ - x̄) / σ)³ / n
```
- 分布の左右対称性を示す
- 0に近い: 左右対称（正規分布に近い）
- 正の値: 右に裾が長い（高い値の外れ値がある）
- 負の値: 左に裾が長い（低い値の外れ値がある）

#### 尖度（Kurtosis）
**計算式**:
```
Kurtosis = Σ((xᵢ - x̄) / σ)⁴ / n - 3
```
- 分布の尖り具合を示す
- 0: 正規分布と同じ尖り具合
- 正の値: 正規分布より尖っている（外れ値が多い）
- 負の値: なだらか（データが均一）

### 信頼区間分析

#### 正規分布におけるσ範囲
データが正規分布に従うと仮定した場合の信頼区間。

**σ1範囲（68.3%）**:
```
[x̄ - σ, x̄ + σ]
```
- 約68.3%のデータがこの範囲に含まれる

**σ2範囲（95.4%）**:
```
[x̄ - 2σ, x̄ + 2σ]
```
- 約95.4%のデータがこの範囲に含まれる

**σ3範囲（99.7%）**:
```
[x̄ - 3σ, x̄ + 3σ]
```
- 約99.7%のデータがこの範囲に含まれる
- この範囲外はほぼ外れ値と見なせる

### サンプルサイズの妥当性判断

#### 必要サンプルサイズの計算
**目的**: 統計的に十分なサンプル数を確保できているかを判定

**計算式**:
```
n = (Z × σ / E)²
```
- Z: 信頼水準に対応するZ値
- σ: 標準偏差
- E: 許容誤差

**信頼水準とZ値の対応**:
- 90%: Z = 1.645
- 95%: Z = 1.960（最も一般的）
- 99%: Z = 2.576

**許容誤差（E）**:
- 推定値と真の値の間で許容できる誤差の大きさ
- 小さいほど精度が高くなるが、より多くのサンプルが必要
- 例: 2.0%なら真の値±2.0%の範囲で推定したい

**判定基準**:
- 実際のサンプル数 ≥ 必要サンプル数: 妥当
- 実際のサンプル数 < 必要サンプル数: 不足

**表示内容**:
- 実際のサンプル数
- 必要サンプル数（小数点以下切り上げ）
- 判定結果（妥当/不足）
- 具体的な説明とアクション

### 外れ値検出（IQR法）

#### IQR法による外れ値検出
**計算式**:
```
外れ値 = データ < Q1 - 1.5×IQR または データ > Q3 + 1.5×IQR
```

**検出範囲**:
```
正常範囲 = [Q1 - 1.5×IQR, Q3 + 1.5×IQR]
```

**表示**:
- 外れ値の件数
- 正常範囲の値
- 外れ値のリスト（行番号と値）

**操作**:
- 外れ値をチェックボックスで選択
- 「すべて選択」「すべて解除」ボタン
- 「外れ値を含む行をテーブルから削除」ボタン
- 削除後は統計が自動再計算される

**視覚化**:
- テーブル上で外れ値を含む行をハイライト表示
- 背景色を赤系に変更
- 行番号を強調表示

### 推奨代表値

#### 自動判定ロジック
**基準**: 歪度の絶対値

**判定ルール**:
```
|歪度| ≤ 0.5 → 平均値を推奨
|歪度| > 0.5 → 中央値を推奨
```

**理由**:
- **平均値**: 分布が対称的な場合に適している
- **中央値**: 分布が歪んでいる場合や外れ値がある場合に適している

**表示内容**:
- 推奨される代表値（平均値 or 中央値）
- 判定理由の説明
- 実際の値

### グラフ表示（ECharts）

#### 対応グラフ種類

**1. 箱ひげ図（Box Plot）**
- データの分布を5つの数値で要約
- 最小値、Q1、中央値、Q3、最大値
- 外れ値を点で表示

**2. ヒストグラム（Histogram）**
- データの度数分布を棒グラフで表示
- ビンの数は自動計算（Sturgesの公式）
- データの偏りを視覚的に確認

**3. 散布図（Scatter Plot）**
- 各データ点をプロット
- データの傾向やパターンを把握
- 加工前重量と歩留まり率の関係を表示

**4. 正規分布曲線（Normal Distribution）**
- 理論的な正規分布曲線をヒストグラムに重ねて表示
- 実際のデータが正規分布に従うかを確認

**5. Q-Qプロット（Q-Q Plot）**
- 実際のデータと理論的な正規分布を比較
- データが正規分布に従う場合、点は直線上に並ぶ
- 正規性の検定に使用

#### 分析対象の切り替え
- **歩留まり率**: 最も一般的な分析対象
- **加工前重量**: サンプルの元の重量の分布を確認
- **加工後重量**: 加工後の重量の分布を確認

**使い方**:
1. 「表示する統計」ドロップダウンで対象を選択
2. 「グラフ種類」ドロップダウンでグラフタイプを選択
3. グラフが自動的に更新される

## セッション管理機能

### セッション自動保存

**概要**: ページリロード後も入力値を自動的に保持する機能

**動作仕様**:
- **保存タイミング**: 入力値が変更されるたびに自動保存
- **保存先**: localStorage（`yieldCalculatorSession`キー）
- **有効期限**: 24時間（期限切れデータは自動削除）
- **保存内容**:
  - 選択中のモード（定額/計量/歩留まり統計）
  - 歩留まり率の入力方法（重量から計算/直接入力）
  - すべての入力フィールドの値
  - 商品化シミュレーションの値
  - 歩留まり統計のテーブルデータ

**実装関数**:
- `saveSessionState(mode)`: 現在の状態をlocalStorageに保存
- `restoreSessionState()`: localStorageからセッションデータを復元（有効期限チェック付き）
- `clearSessionState()`: セッションデータをクリア
- `applySessionState(sessionData)`: セッションデータから入力フィールドを復元

**セッションデータ構造**:
```javascript
{
  mode: "fixed" | "weight" | "yieldStats",
  yieldMethod: "calculate" | "direct",
  timestamp: 1706400000000,  // 保存日時
  inputs: {
    // モード別の入力値
  },
  simulation: {
    expWeight: "100",
    consumable: "10"
  },
  tableData: [
    // 歩留まり統計のテーブルデータ（yieldStatsモードのみ）
  ]
}
```

**使用例**:
1. ユーザーが入力を開始
2. 入力値が自動的にlocalStorageに保存される
3. ブラウザを閉じる/ページをリロードする
4. アプリ起動時に自動的に入力値が復元される
5. 24時間経過後は自動的にクリアされる

## データ管理機能

### 保存機能

#### カテゴリー優先の保存フロー
**手順**:
1. 計算完了後、「💾 この計算を保存」をクリック
2. **カテゴリーを選択**（野菜/果実）
3. **商品名を入力**
   - カテゴリーに応じた商品名候補が表示される
   - 既存の商品名から選択または新規入力
4. 保存ボタンをクリック

**カテゴリー別フィルタリング**:
- カテゴリーを選択すると、そのカテゴリーに属する商品名のみが表示
- 例: 「野菜」を選択 → データベース内の野菜カテゴリーの商品名のみ表示

**保存されるデータ**:
- 商品名
- カテゴリー
- 計算モード（定額/計量）
- 入力値（原価、売価、重量、歩留まり率など）
- 計算結果（値入率、粗利率など）
- 商品化データ（パック重量、消耗品費など）
- 値引後最終粗利率
- タイムスタンプ

### 履歴管理

#### 履歴表示
**表示項目**（2行レイアウト）:

**1行目**:
- 1個（箱）あたりの原価
- 1個（箱）あたりの売価
- 加工前値入率
- 加工後値入率

**2行目**:
- 歩留まり率
- 最終粗利率（値引後）

**その他の情報**:
- モードラベル（定額売価/計量売価）：品名の左側にバッジ表示
- 商品名

## Firebase連携機能 🆕

### 概要

**バージョン**: v4.2で実装
**目的**: マルチデバイス対応、データの永続化、クラウド同期

歩留まり計算ツールは、**2層のデータ永続化戦略**を採用しています：
1. **IndexedDB（ローカル）**: オフライン対応、高速アクセス
2. **Firebase Firestore（クラウド）**: オンライン同期、マルチデバイス対応

---

### 主要機能

#### 1. Firebase Authentication（ユーザー認証）

**対応認証方式**:
- Google認証（Googleアカウントでログイン）
- Email/Password認証

**ログイン状態の表示**:
- ヘッダーに「☁️ ログイン中」または「☁️ 未ログイン」と表示
- ユーザー名/メールアドレスを表示

**操作**:
- ログインボタン: 認証モーダルを開く
- ログアウトボタン: メニューから実行

---

#### 2. Firestore（クラウドデータベース）

**データ構造**:
```
users/{userId}/history/{uuid}
  - name: 商品名
  - category: カテゴリー（vegetable/fruit）
  - mode: 計算モード（fixed/weight）
  - input: 入力データ
  - result: 計算結果
  - product: 商品化データ
  - timestamp: 保存日時
  - deleted: 論理削除フラグ
```

**特徴**:
- **論理削除**: 削除したデータも復元可能（監査証跡を保持）
- **UUID管理**: FirestoreのドキュメントIDとIndexedDBのレコードを紐付け
- **タイムスタンプ**: 更新日時で競合解決

---

#### 3. 自動同期

**同期タイミング**:
- ✅ アプリ起動時: Firestoreから全データ取得 → IndexedDB更新
- ✅ 履歴モーダルを開く: 表示前に同期
- ✅ 読込ボタンクリック: 読み込み直前に再同期
- ✅ 保存/更新/削除後: Firestore操作 → IndexedDBキャッシュ

**同期フロー**:
```
オンライン時:
  Firestore (信頼できる唯一のソース) ⇄ IndexedDB (キャッシュ)

オフライン時:
  IndexedDB (ローカルキャッシュのみ)
```

**実装ファイル**:
- `scripts/firebase-sync.js`: 同期ロジック
- `scripts/firebase-auth.js`: 認証管理
- `scripts/firebase-config.js`: Firebase設定

---

#### 4. CRUD操作の仕様

| 操作 | オンライン | オフライン | 動作 |
|------|----------|----------|------|
| **Create** | Firestore → IndexedDB | ❌ エラー | Firestoreに保存後、IndexedDBにキャッシュ |
| **Read** | Firestore → IndexedDB | ✅ IndexedDB | キャッシュから読み込み、表示前に同期 |
| **Update** | Firestore → IndexedDB | ❌ エラー | Firestoreを更新後、IndexedDBキャッシュを更新 |
| **Delete** | Firestore → IndexedDB | ❌ エラー | Firestoreで論理削除後、IndexedDBも更新 |

**オフライン時の制限**:
- 保存/更新/削除はオンライン時のみ可能
- 読み込みはオフラインでも可能（IndexedDBキャッシュを使用）

**理由**: データの整合性を保証するため、Firestoreを信頼できる唯一のソース（Single Source of Truth）とする

### パフォーマンス最適化（v4.2新設）

#### デバウンス処理

**実装**: `scripts/debounce.js`（85行）

**目的**: 入力イベントハンドラーの過剰な実行を抑制し、パフォーマンスを改善

**適用箇所**（19箇所）:
- ステップハンドラー（13箇所）
  - Step 1-3（定額モード・重量から計算）
  - Direct Step 1-3（定額モード・直接入力）
  - Weight Step 1-3（計量モード・重量から計算）
  - Weight Direct Step 1-3（計量モード・直接入力）
  - 商品化シミュレーション
  - 値引きシミュレーション
  - 逆算シミュレーション
  - サンプルサイズ検証
- 複数パターンUI（6箇所）
  - 加工前後の重量入力
  - 目標値入率スライダー
  - 各パターンの入力フィールド

**デバウンス遅延**: 300ms（`TIME.DEBOUNCE_DELAY`）

**提供関数**:

1. **debounce(func, delay)**
   - 標準的なデバウンス（trailing edge）
   - ユーザーが入力を停止してから300ms後に実行
   - 用途: 通常の入力フィールド

2. **debounceLeading(func, delay)**
   - リーディングエッジデバウンス
   - 最初のイベントは即座に実行、その後は遅延
   - 用途: 即座のフィードバックが必要な場合

3. **throttle(func, limit)**
   - スロットル処理
   - 指定時間内に最大1回のみ実行
   - 用途: スクロールイベントなど高頻度イベント

**特殊な実装**:
- **Map-based handler management**: 動的に生成されるパターン行のメモリリーク防止
- パターン削除時にデバウンスハンドラーも自動クリーンアップ

**効果**:
- 入力時の不要な再計算を削減
- UIのレスポンシブ性向上
- CPU使用率の削減
- バッテリー消費の抑制

**使用例**:
```javascript
import { debounce } from './debounce.js';
import { TIME } from './constants.js';

const debouncedHandler = debounce(handleCalculation, TIME.DEBOUNCE_DELAY);
inputElement.addEventListener('input', debouncedHandler);
```

- 統計ロードボタン: 62行 → 39行（37%削減）
- 合計: 約80行のコード削減

**効果**:
- 保守性の向上

- **履歴読み込み後の制御**:
  - 履歴から読み込んだ計算は、変更がない場合は保存ボタンを無効化
  - 入力値を変更すると保存ボタンが有効化される
- **フラグベースの状態管理**:
  - `isFromHistory`: 履歴から読み込まれた計算かどうか
  - `hasUnsavedChanges`: 未保存の変更があるかどうか
- **重複保存の防止**: 同じ計算を複数回保存することを防ぐ

### AppState状態管理の拡張
- `markAsFromHistory()`: 履歴から読み込んだことをマーク
- `markAsNewCalculation()`: 新規計算としてマーク
- `markAsChanged()`: 変更があったことをマーク
- `markAsSaved()`: 保存済みとしてマーク
- `isFromHistoryRecord()`: 履歴からの読み込みかどうかを判定
- `hasChanges()`: 未保存の変更があるかどうかを判定

### フィルタリング機能の改善
- 歩留まり統計モードのフィルタリング問題を修正
- `yieldMethod` が未保存の古いデータでもフィルタが正常に動作

## Phase 9 UX改善 🆕

### 概要

### アニメーション効果

#### 1. フェードインアニメーション（fadeIn）
**対象**: 基本的な表示要素
**効果**: 要素が滑らかに表示される
**実装**: CSS keyframes animation
```css
@keyframes fadeIn {
  from { opacity: 0; }
  to { opacity: 1; }
}
```

#### 2. フェードインアップアニメーション（fadeInUp）
**対象**: マトリックス評価、統計値グループ
**効果**: 下から上にスライドしながらフェードイン
**実装**: CSS keyframes animation
```css
@keyframes fadeInUp {
  from {
    opacity: 0;
    transform: translateY(20px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}
```

#### 3. スケールインアニメーション（scaleIn）
**対象**: 推奨代表値バッジ
**効果**: 中心から拡大して表示
**実装**: CSS keyframes animation
```css
@keyframes scaleIn {
  from {
    opacity: 0;
    transform: scale(0.8);
  }
  to {
    opacity: 1;
    transform: scale(1);
  }
}
```

#### 4. カウントアップアニメーション
**対象**: サンプルサイズ検証のサンプル数、充足率
**効果**: 数値が0から目標値まで段階的にアニメーション
**実装**: JavaScript + requestAnimationFrame
**適用箇所**:
- 現在のサンプル数
- 必要サンプル数
- サンプルサイズ充足率

### カラーコーディング

#### 色の意味
- **緑（#28a745）**: 良好・十分・合格
- **黄（#ffc107）**: 警告・要注意・ギリギリ
- **赤（#dc3545）**: 危険・不足・不合格

#### 適用箇所

**1. マトリックス評価**
- 🌟 優秀（緑）: CV ≤ 3%、サンプル数 ≥ 必要数
- ✓ 良好（緑）: CV ≤ 5%
- ⚡ 要注意（黄）: CV > 5%
- ⚠️ 改善推奨（黄/赤）: その他

**2. サンプルサイズ検証**
- 緑: 充足率 ≥ 100%（十分なサンプル数）
- 黄: 充足率 80-99%（やや不足）
- 赤: 充足率 < 80%（大幅に不足）

**3. プログレスバー**
- プログレスバーの色が充足率に応じて変化
- 背景色も状態に応じて調整

### プログレスバー表示

**対象**: サンプルサイズ検証
**目的**: サンプル数の充足度を視覚的に表示
**実装**:
```html
<div class="sample-size-progress">
  <div class="progress-bar" style="width: 75%; background-color: #ffc107;">
    75%
  </div>
</div>
```

**動作**:
- 現在のサンプル数 ÷ 必要サンプル数 × 100 = 充足率
- プログレスバーの幅が充足率に応じて変化
- 色も自動的に変更（緑/黄/赤）

### アイコン付き表示

**目的**: 視覚的な情報伝達を強化

**使用アイコン**:
- 🌟: 優秀な結果
- ✓: 良好
- ⚡: 要注意
- ⚠️: 警告
- 📊: 統計情報
- 📈: データ分析
- 🎯: 目標・推奨

**適用箇所**:

- 推奨代表値のバッジ
- エラーメッセージ

### 段階的表示（ステージング）

**目的**: 認知負荷の軽減

**実装方法**:

**コード例**:

```javascript
statsItems.forEach((item, index) => {

    item.classList.add('fadeIn');
  }, index * 50);
});
```
